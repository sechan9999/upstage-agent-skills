# Skill: Ops Control Center (운영 관제 센터)

> 쏟아지는 알림·로그·지표를 받아 **"무엇이 바뀌었나 / 어디에 집중됐나 / 무엇부터 조치할까"**의
> 우선순위 브리핑으로 바꾸고, **사람이 승인할** 조치안을 제시합니다.

**환경:** 타임리 Agent × Solar Pro 4

---

## 언제 쓰나 (Trigger)
- 시스템/비용/에러/보안 알림이 한꺼번에 쏟아져 상황 파악이 안 될 때
- "이 로그 좀 정리해줘", "지금 뭐부터 봐야 해?", "대시보드 요약해줘"
- 장애·비용 급증·이상 징후 대응 우선순위가 필요할 때

## 입력 (Input)
- 알림/로그/지표 목록 (붙여넣은 대시보드 텍스트, CSV, 알림 리스트 등)
- (선택) 정상 기준선 (예: "평소 시간당 비용 $2", "에러율 1% 이하")

## 동작 (Instructions)
1. **정규화** — 잡음을 걷어낸다. 같은 원인의 중복 알림을 하나로 병합하고, 정보성 로그와 실제 이상을 분리한다.
2. **이상 탐지** — 기준선 대비 무엇이 비정상인가. **시간대를 고려**한다 (피크 시간의 $5는 정상, 새벽의 $5는 이상).
3. **영향 분석** — 각 이상이 무엇/누구에게 영향을 주나. 연쇄(dependency)를 추적한다 — 이 하나가 무엇을 무너뜨리나.
4. **우선순위** — 심각도 × 긴급도로 정렬. "시끄럽지만 안전한 것"과 "조용하지만 위험한 것"을 구분한다.
5. **조치안** — 각 이슈에 권장 조치를 붙이고, 각 조치가 **가역(reversible)인지 비가역인지** 표시한다.
6. **브리핑 출력** — 요약을 먼저, 상세를 나중에. 사람이 5초 안에 "뭐부터"를 알 수 있게.

## 출력 형식 (Output)
```
📊 한 줄 요약: (지금 상황을 한 문장으로)

🔴 즉시 조치 (N건)
  • [무엇] — 영향: [누가/무엇] · 권장: [조치] · 가역성: [가역/비가역·승인필요]
🟠 주의 관찰 (N건)
  • ...
🟢 정상 / 노이즈 (N건 요약)

▶ 추천 첫 조치: (딱 하나, 지금 바로 할 것)
```

## 예시 (Example)
- 입력: "cost=$9.2/h (기준 $2), latency=6500ms(기준 800ms), 3x 'timeout' 로그, 1x 'cache miss', 배포 v2.3 12:04"
- 출력:
  - 📊 12:04 v2.3 배포 직후 비용·지연 동시 급등 — 배포가 원인일 가능성 높음
  - 🔴 비용 4.6배 급등 → 권장: 저비용 모델로 폴백 + 캐시 강화 (가역·승인 후) / 지연 8배 → 같은 원인 의심
  - 🟢 cache miss 1건은 노이즈
  - ▶ 추천 첫 조치: v2.3 롤백 여부를 사람에게 확인 (비가역 아님, 5분 내 복구 가능)

## 주의 (Guardrails)
- **파괴적/비가역 조치는 절대 자동 실행하지 않는다.** 롤백·삭제·차단·환불 등은 반드시 사람 승인 후.
- 데이터가 부족하면 추측하지 말고 "판단하려면 X가 더 필요"라고 말한다.
- 알림이 곧 이상은 아니다 — 리포팅 아티팩트(집계 지연, 배치 업로드)를 실제 이상과 구분한다.
