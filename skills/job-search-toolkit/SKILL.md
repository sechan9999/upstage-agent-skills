# Job Search Toolkit

## 스킬의 범위와 한계 (먼저 읽을 것)

- 이 스킬의 스코어링은 **정확한 표면 표현 겹침(exact surface expression overlap)**을 측정하도록 설계된 스크립트(`scripts/score_posting.py`)에 의존한다.
  - **영어/라틴 텍스트**: 단어 경계(`\b[A-Za-z][A-Za-z0-9+#./-]*\b`), ASCII 소문자 정규화, 기본 영어 불용어(Stopwords) 제거, 미인식 대문자 약어(2~6자) 분리 처리를 수행한다.
  - **한국어/일본어 텍스트**: 공백 및 구두점(`CJK_SPLIT_RE`)으로 분리된 표면 청크를 키워드로 추출한다. **형태소 분석기는 사용하지 않는다.** 따라서 `Python과`, `API를`, `클라우드에`처럼 조사가 결합된 청크 단위로 처리되며, 노이즈가 발생할 수 있다.
  - **렉시콘(`--lexicon`)**: 여러 단어로 이루어진 복합 기술 용어(예: `machine learning`, `대규모 분산 시스템`, `React Native`, `구글 클라우드 플랫폼`, `CI/CD 파이프라인`, `機械学習`)는 렉시콘 파일에 등록하면 문서 전체에서 완전한 단일 단위로 매칭되어 쪼개짐이나 조사 왜곡을 방지한다.
- 스크립트가 측정하는 것은 **"두 문서에 동일한 표면 표현이 함께 등장하는가"**뿐이다.
  공고의 `cross-functional collaboration`과 이력서의 `여러 부서와 협업`, `worked with other teams`처럼 **다른 말로 표현된 동일 요건을 의미적으로 같다고 임의 추론하지 않는다.**
  의미적 추론은 비결정적이고 모델마다 편차가 발생하여 감사(Audit)가 불가능해지기 때문이다.
  따라서 스크립트가 도출한 공백(Gap)은 "표현상 공백"으로 해석하며, 실제 역량 보유 여부는 사람이 확인한 뒤에만 최종 조치를 취한다.
- **단일 커버리지 수치 하나로 적합/부적합을 판정하지 않는다.**
  숫자는 갭 목록, 제약 정보, 인식되지 않은 공고 표현, 그리고 **카테고리별 커버리지(required / preferred / unmarked)**와 반드시 함께 입체적으로 읽어야 한다. 전체 커버리지가 80%로 높아도 필수 요건(required)이 빠져 있으면 탈락 위험이 크고, 커버리지가 40%로 낮아도 필수 요건을 모두 충족하고 우대사항(preferred)만 비어 있다면 충분히 지원 가능한 포지션일 수 있다.
- **필수/우대 분류는 근접 기반 휴리스틱(Proximity Heuristic)으로 분리된다.**
  공고 텍스트에서 필수 마커(`required`, `must`, `필수`, `필수요건` 등) 또는 우대 마커(`preferred`, `nice to have`, `우대`, `우대조건` 등) 근처(반경 250자 이내)에 등장한 키워드를 해당 버킷으로 분류한다.
  공고가 섹션별로 명확하게 필수/우대를 구분해 두었다면 원문의 구분을 최우선으로 존중하고, 스크립트의 버킷 분류는 보조 지표로 활용한다.

## 왜 이 스킬이 필요한가

겉보기에 그럴듯한 매칭 점수를 내주는 도구는, 실제로 작동하는 도구와 구별되지 않는다.
차이는 그 숫자를 실제 채용 전형에서 검증했을 때만 드러난다.

초반 단순 LLM 프롬프트 방식의 워크플로는 라미네이트 도우 성형, 오전 5시 근무 시작, "컴퓨터 사용 불가"가 명시된 제과·파티시에 채용 공고에 일반 IT 이력서를 넣었을 때 92% 적합 판정을 내리는 치명적인 결함을 보인 적이 있다. 모델이 구체적인 검증 가능 조건을 확인하지 않고 피상적인 분위기만 패턴 매칭했기 때문이다.

이 스킬은 이러한 치명적 실패를 원천 차단하기 위해 존재한다:
1. 계산할 수 있는 결정론적 수치는 코드로 엄격하게 계산한다.
2. 문서에 명시되지 않은 제약은 추측하지 않고 `"NOT STATED"`(명시되지 않음)로 남긴다.
3. 원본 문서에 없는 가공의 경력이나 기술을 생성하지 않는다.

## 네 가지 핵심 명령

사용자가 요청한 작업 범위에 맞춰 정확히 필요한 워크플로를 실행한다. (보통은 하나씩 단계별로 진행한다)

1. **공고 점수 산출 (Score)** — 이력서와 공고 간 키워드 커버리지(전체 및 카테고리별)와 갭을 계산한다.
2. **CV 맞춤 수정 (Tailor CV)** — 후보자가 실제 보유한 경험을 해당 공고의 우선순위에 맞게 재배치하고 명확화한다.
3. **자기소개서 초안 작성 (Cover Letter)** — 두 문서 간 실제 일치하는 핵심 역량을 근거로 진실한 편지를 작성한다.
4. **면접 준비 팩 작성 (Interview Prep)** — 공고 요건과 이력서 공백(Gap)에서 면접관이 파고들 예상 질문과 대응 논리를 수립한다.

## 사실 근거 규칙 (Fact-Grounding Rules - 모든 명령 공통)

이 규칙은 스타일 권고가 아니라 시스템의 무결성을 지키는 절대 규칙이다:

1. **표현 정제와 구조 재배치는 장려하되, 허위 창작은 절대 금지한다.**
   - "운영팀을 위한 도구를 만들었다"를 공고의 표현에 맞춰 "운영 효율화를 위한 내부 어드민 툴링 개발"로 명확하게 다듬는 것은 권장된다.
   - 그러나 이력서에 없는 기술 스택, 부풀려진 수치, 인증서, 경력 연수 등을 임의로 추가하는 것은 엄격히 금지된다.
2. **해석할 수 없는 공고 표현은 점수에서 조용히 빼지 말고 사용자에게 명시한다.**
   - 스크립트가 파싱하지 못하거나 사전/렉시콘에 없는 특수 도구명, 내부 약어 등은 `unrecognized_posting_language`로 분리하여 사용자에게 보고하고 의미를 확인받는다.
3. **명시되지 않은 제약은 "NOT STATED"로 보고하며, 결코 추측하지 않는다.**
   - 공고에 급여, 근무 형태(원격/하이브리드/출근), 최소 요구 경력이 적혀 있지 않으면 기본값을 가정하지 않고 `NOT STATED`로 표기하며, 면접 시 후보자가 질문할 "역질문 후보"로 전환한다.
4. **주관적인 당락 판정이나 감상적 평가를 내리지 않는다.**
   - "합격 유력", "적극 추천", "완벽한 매칭"과 같은 주관적 단정을 하지 않는다.
   - 커버리지는 두 문서 텍스트 간의 일치율일 뿐이며, 채용 결정은 정성적 역량과 컬처핏을 포함하여 사람이 내린다.
5. **모호한 용어와 실제 문맥을 구분한다.**
   - "하이브리드 검색", "하이브리드 클라우드" 같은 기술 용어를 "하이브리드 근무(원격+출근)"로 오분류하지 않도록 스크립트 가드(`WORK_ARRANGEMENT_DISQUALIFIERS`)와 원문 문맥을 함께 확인한다.
6. **대화 중 새로 밝혀진 사실의 명확한 출처 태깅:**
   - 대화 도중 사용자가 "사실 그 프로젝트에서 X도 담당했다", "자격증이 있지만 이력서에 누락했다"고 추가 사실을 진술할 경우, 이를 반영할 수 있다.
   - 단, 이 내용은 반드시 문장이나 구 바로 뒤에 `[신규 확인: 대화에서 직접 밝힘]` 태그를 부착한다.
   - 예시: `사내 실시간 이상 징후 감지 파이프라인 구축 및 Kafka 연동 [신규 확인: 대화에서 직접 밝힘]`
   - 사용자가 최종 승인하기 전까지는 초안 및 보고서 전반에서 이 태그를 절대 삭제하지 않는다.

## CLI 실행 및 JSON 연동 가이드

`scripts/score_posting.py`는 외부 라이브러리 의존성 없이 Python 3 표준 라이브러리만으로 동작한다.

### 실행 명령어

```bash
# 1. 기본 텍스트 리포트 실행
python scripts/score_posting.py resume.txt posting.txt

# 2. 복합 용어 렉시콘 적용 실행
python scripts/score_posting.py resume.txt posting.txt --lexicon lexicon.txt

# 3. JSON 포맷 출력 (자동 파이프라인 및 LLM 정밀 분석용)
python scripts/score_posting.py resume.txt posting.txt --lexicon lexicon.txt --json
```

### 렉시콘(`lexicon.txt`) 작성 팁
- 한 줄에 하나의 복합 기술명이나 고유명사를 작성한다 (`#` 주석 지원).
- 예시:
  ```text
  # 핵심 기술 스택
  machine learning
  대규모 분산 시스템
  Kubernetes
  React Native
  PostgreSQL
  Spring Boot
  CI/CD 파이프라인
  ```

### JSON 출력 데이터 구조
```json
{
  "overall_coverage_pct": 68.4,
  "overall_matched": 13,
  "overall_total": 19,
  "category_coverage": {
    "required": { "matched": 7, "total": 8, "pct": 87.5 },
    "preferred": { "matched": 4, "total": 7, "pct": 57.1 },
    "unmarked": { "matched": 2, "total": 4, "pct": 50.0 }
  },
  "matched_terms": ["docker", "python", "sql"],
  "gap_terms": ["graphql", "kafka"],
  "gap_terms_by_category": {
    "required": ["kafka"],
    "preferred": ["graphql", "redis"],
    "unmarked": []
  },
  "constraints": {
    "salary": "$140,000 - $170,000",
    "work_arrangement": "remote (matched \"remote\", context: \"...\")",
    "years_experience": "5+ years"
  },
  "unrecognized_posting_language": ["APM", "GRPC"]
}
```

## 단계별: 공고 점수 산출 (Command 1)

1. **언어 및 입력 상태 확인**:
   - 영문 전용: 표준 파이프라인 실행.
   - 한글/다국어 혼합: 표면 청크 특성을 고려하여, 핵심 도메인 용어 누락을 방지하기 위해 사용자가 제공한 주요 기술 목록을 렉시콘으로 지정하거나, 스크립트 실행 후 노이즈를 필터링할 준비를 한다.
2. **스크립트 실행**:
   - `python scripts/score_posting.py resume.txt posting.txt [--lexicon lexicon.txt] [--json]` 실행.
3. **점수 리포트 출력 표준**:
   - **전체 커버리지**: 일치 건수 / 전체 요건 건수 및 백분율.
   - **카테고리별 커버리지**:
     - 필수(Required): X/Y (Z%) — *최우선 판별 지표*
     - 우대(Preferred): X/Y (Z%) — *경쟁력 가산 지표*
     - 미분류(Unmarked): X/Y (Z%)
   - **제약 조건(Constraints)**: 급여, 근무 형태, 요구 경력 (미명시 시 NOT STATED 명시).
   - **매칭된 핵심 키워드**: 이력서와 공고 모두에 존재하는 기술/경험 목록.
   - **카테고리별 갭(Gap) 분석**:
     - 필수 요건 갭 (Hard Gaps): 반드시 면접/서류에서 소명하거나 보완해야 할 치명적 공백.
     - 우대 요건 갭 (Soft Gaps): 선택적 항목으로 인한 공백.
   - **인식되지 않은 약어/표현**: 추가 확인이 필요한 용어.
4. **4단계 해석 코멘터리 제공**:
   - 단순 표면 일치와 실제 의미 일치의 차이 분석 (예: 공고의 '협업' vs 이력서의 '크로스펑셔널 팀 리드').
   - 조사 결합으로 인한 표면 노이즈 식별 및 정제 안내.
   - 실질적 결격 사유 유무 진단 (필수 갭 중 실제 보유 여부 문의).

## 단계별: CV 맞춤 수정 (Command 2)

1. **매칭 결과 분석**:
   - 스코어링 단계의 `matched_terms`와 `gap_terms_by_category`를 기초 데이터로 사용한다.
2. **일치 항목의 가시성 극대화**:
   - 이력서에 이미 존재하지만 눈에 띄지 않거나 다른 용어로 표현된 실제 경험을 공고의 공식 용어와 자연스럽게 일치하도록 문맥을 정돈한다.
   - 중요 일치 항목을 직무 요약(Summary)이나 각 경력의 상단 불릿으로 재배치한다.
3. **공백(Gap) 항목의 정직한 처리**:
   - 없는 경험을 끼워 넣지 않는다.
   - 대화 중 사용자가 "실제 수행했으나 이력서에 누락되었다"고 확인한 사실만 `[신규 확인: 대화에서 직접 밝힘]` 태그와 함께 추가한다.
   - 완전히 경험이 없는 필수 갭은 무리하게 채우지 않고, 후속 자기소개서/면접에서 인접 기술 전이 능력으로 풀어내도록 남겨둔다.
4. **산출물 구성**:
   - **수정된 맞춤 CV 전문**
   - **변경 내역 요약 표 (Diff Summary Table)**:
     | 구분 / 위치 | 기존 원문 표현 | 맞춤 수정 표현 | 수정 사유 및 근거 | 출처 |
     | :--- | :--- | :--- | :--- | :--- |
     | 경력 1 (ABC사) | 백엔드 API 개발 | 대규모 분산 환경에서 REST API 설계 및 성능 튜닝 | 공고 필수요건 키워드 매칭 및 성과 구체화 | 이력서 원문 |
     | 기술 스택 | Python, MySQL | Python, MySQL, Kafka 연동 파이프라인 설계 | 공고 필수요건 반영 | 신규 확인 (대화) |

## 단계별: 자기소개서 초안 작성 (Command 3)

1. **핵심 앵커(Anchor) 선정**:
   - 모호하고 추상적인 열정 나열을 지양하고, 점수 산출에서 확인된 **검증된 일치 역량 중 가장 임팩트 있는 2~3개 핵심 프로젝트/성과**를 글의 중심 축으로 설정한다.
2. **갭(Gap)에 대한 정직하고 전략적인 접근**:
   - 공고에서 강조하지만 이력서에 부족한 영역을 거짓으로 얼버무리지 않는다.
   - 인접 기술 경험(예: Kafka 경험은 없으나 RabbitMQ 대규모 운영 경험 보유)을 기반으로 빠른 학습 곡선과 적용 가능성을 정직하고 논리적으로 서술한다.
3. **글의 구조**:
   - **도입부**: 해당 직무 및 기업의 핵심 미션에 대한 공감과 지원자의 핵심 강점 요약.
   - **본문 1 (일치 역량 증명)**: 앵커 1에 대한 구체적 문제 상황, 해결 행동, 정량적/정성적 성과.
   - **본문 2 (협업 및 확장 역량)**: 앵커 2에 대한 증명 및 공고의 핵심 과제와의 직접적 연결.
   - **본문 3 (도전 과제 및 갭 극복)**: 미보유 요건에 대한 진솔한 관심과 인접 경험 기반의 학습 실행 계획.
   - **결론**: 입사 후 기여 비전.

## 단계별: 면접 준비 팩 작성 (Command 4)

1. **갭 기반 압박 질문 방어 (Gap Defense)**:
   - 면접관이 가장 집요하게 검증할 부분은 **공고의 필수 요건(required) 중 이력서에 없는 갭**이다.
   - 각 갭별 예상 질문을 도출하고, STAR (Situation - Task - Action - Result) 프레임워크에 기반한 정직하고 현실적인 답변 가이드를 작성한다.
   - "모르는 것을 아는 척하는 답변"이 아니라, "현재 이해도 + 유사 기술 경험 + 습득 계획"을 당당하게 설명하는 스크립트를 제공한다.
2. **핵심 강점 심층 질문 대비**:
   - 매칭된 핵심 역량에 대해 면접관이 기술적 깊이를 확인할 수 있는 심화 기술 질문 및 설계 의도 질문을 제시한다.
3. **제약사항 기반 전략적 역질문 (Reverse Questions)**:
   - 스크립트에서 `"NOT STATED"`로 도출된 제약사항(예: 명시되지 않은 근무 방식, 팀 규모, 온콜 로테이션, 배포 주기, 기술 부채 해결 우선순위 등)을 후보자가 면접관에게 물어볼 수 있는 품격 있고 전문적인 역질문 목록으로 완성한다.
